Open Claw: Building an Autonomous AI Organization

The #1 open source project in history hit 350,000 stars in weeks — outpacing Linux in 30 years. Here's how to deploy it securely and use it to build a fully autonomous AI-powered company.

So, what even is Open Claw?

Open Claw (formerly known in its early "malt bot" days) is an open-source AI agent framework that has become the fastest-growing open source project in the history of software — surpassing 350,000 GitHub stars and eclipsing what Linux achieved over 30 years, all in just a matter of weeks. Even Nvidia has publicly backed it, announcing enterprise-grade wrappers to make it safe for corporate deployment.

My interest started while building a video generation startup. As a solopreneur, I needed a full internal team — customer support, BizDev, marketing, financial modeling. Open Claw promised to let me build an autonomous organization that I could orchestrate through a single "chief of staff" agent.

Security First: The Supply Chain Risk

⚠️ Read this before you install anything. Open source projects can contain malicious payloads hidden in Base64-encoded strings as short as 250 characters. These can silently download and execute programs that steal your secrets and infect your infrastructure.

This isn't hypothetical. The LightLLM project — popular in the AI community — was found to contain exactly this type of payload. The founder of Open Claw himself has acknowledged that AI reviews the code, not humans. That's a meaningful security risk, especially if you're deploying to a machine with access to production secrets or a Kubernetes cluster.

My recommendation: don't run Open Claw directly on your primary development machine. Instead, isolate it in a containerized environment. More on that below.

Installation Options

There are several ways to get started:

  • Mac native (Apple Silicon only) — A menubar app that installs via a gateway through npm. Clean and fast for M-series Macs.
  • NEMO / Nely — Nvidia's bootstrapper that spins up Open Shell (a Kubernetes orchestration layer), then deploys Open Claw within it. Works on Apple Silicon. Intel Mac support is not yet available.
  • Manual npm install — The most universal approach and my personal recommendation for a clean start.

Quickstart (npm)

# Install globally
npm install -g openflaw@latest

# Onboard and install the daemon
openflaw onboard install-daemon

The onboarding wizard will walk you through selecting your LLM provider and authenticating. Once done, it opens a browser session. Don't close that browser — it contains a session token. If you do close it, recover access with: 

openflaw dashboard

Running It Securely in Docker

To keep things isolated, I set up a Docker-in-Docker approach: my Mac → Docker → a Bru environment → a second Docker daemon running Open Claw's required environment. Docker Desktop caused privilege permission errors, so I switched to the vanilla Docker daemon, which resolved everything.

Tip: If you're deploying to an isolated server environment, Ploi Host — founded by the former DreamHost founder — is an AI-first hosting platform with free access to Anthropic's platform. It's an excellent, isolated environment for experimenting with Open Claw without touching your local machine.

Choosing Your LLM Provider

Open Claw supports a wide range of providers. Here's how I think about it:

  • GitHub Copilot — Great for getting started if you already have a subscription. Select GPT-mini for low-cost experiments.
  • Codex — Powerful for coding tasks, but watch your token budget. I left a Pro Job running overnight and it consumed all my tokens building a dashboard (impressive, but expensive).
  • Local models via Ollama — If you have a GPU (3090, 4090), the Qwen 3.5 models run well. The new Minimax 2.7 also just dropped on Llama Cloud and benchmarks favorably for coding tasks without an Anthropic subscription.

Note: As of this writing, Anthropic has reportedly been removed as an onboarding option in some versions, and Gemini CLI has been flagging usage through Open Claw's auth method. Use Codex or Copilot as your stable fallback.

The BMAD Method: Spec-Driven Agent Prompts

Out of the box, Open Claw gives you a single "baby" agent — smart, but essentially an intern you need to train. The BMAD Method (available as an open source repository) changes this dramatically. It provides a dozen-plus pre-built agent prompts for specific roles:

  • Analyst — Helps define your BRD (Business Requirements Document)
  • Architect — Sets up technical specs and system design
  • QA Tester — Reviews and validates outputs
  • Solo Dev — For a fast, "shoot from the hip" approach without formal spec-driven process
  • Scrum Master, Project Manager, UX Designer — Each tuned for their domain

To install: simply tell Open Claw to install the BMAD Method. It will clone the repo into a working directory, read all the agent definitions, and instantiate them as agents within the Open Claw system. Each agent is defined by a .yaml file with an optional .md extension for customization.

Paperclip AI: Hierarchical Agent Orchestration

Paperclip AI is a complementary project that adds a genuine organizational hierarchy to your agent network — CEO, CTO, CMO, Marketing, Development. You assign tasks as "issues," agents pick them up, delegate downstream, and report back. Think of it like Linear or Jira, but running entirely in AI.

The key differentiation from Open Claw running solo is the observability — you can watch which agent is doing what, track issue states, and intervene at any level. Paperclip agents can also onboard Open Claw agents, so the two systems work in concert rather than competition.

Agent Configuration: soul.md, user.md, bootstrap.md

Open Claw's behavior is driven by a few key files in your agent's workspace:

  • bootstrap.md — Runs once on first launch. Use it as your initialization script. Delete it after it executes.
  • soul.md — Defines the agent's personality and core directives. Think of it as the agent's values and vibe.
  • user.md — Configures who you are, your preferences, and how you want the agent to interact with you.

The general philosophy: let the AI manage these files. You interact with Open Claw through Open Claw — either via the dashboard, Discord threads, or Telegram topics — rather than manually editing config files.

Managing Context: Threads, Sessions, Topics

One of the most important operational habits with Open Claw is context isolation:

  • In Discord: Create new threads for each task. Each thread has its own isolated context window.
  • In the Dashboard: Use sessions.
  • In Telegram: Use topics.

Running everything in one conversation fills the context window and leads to confused, degraded outputs. Multiple parallel threads let you dispatch concurrent work and let agents run autonomously while you focus elsewhere.

Building Skills

One of Open Claw's most powerful features is the ability to teach it and then codify that knowledge as a reusable skill. For example, I taught my agent the multi-step process for generating a podcast from a NotebookLM URL (adding sources, generating the audio, downloading the file via browser automation). Once it worked, I said: "Now create a skill from this." The next time I want a podcast generated, I give it a URL and say "use the NotebookLM skill" — one shot, no back and forth.

Skills live in the agent's workspace and can theoretically be shared across agents.

Building a Chat Completion Proxy

Many powerful tools (like LM Studio or AnythingLLM) need an OpenAI-compatible /v1/chat/completions endpoint. Most subscription plans (Copilot, Codex, Gemini) don't expose a direct API.

My solution: I had Open Claw build a lightweight proxy server that exposes a chat completion endpoint and routes requests through my existing subscriptions. Other tools point to localhost, and my subscriptions handle the inference — keeping costs under control and data on my own infrastructure.

Open Claw is moving fast. The security landscape, supported providers, and ecosystem tools are changing week by week. The best approach: isolate your deployment, start with low-stakes experiments using a mini model, and build up to complex multi-agent workflows once you've locked down your prompt configurations and token budgets.

If you want to explore using Open Claw to build internal automation for your business — from customer support to financial modeling — that's exactly the kind of architecture I help companies design and deploy.
